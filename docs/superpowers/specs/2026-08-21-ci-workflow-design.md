# Continuous Integration Workflow Design

## Goal

Add a continuous integration workflow that builds, tests, lints, and verifies generated provider
documentation on every pull request and every push to `main`. Keep the future acceptance-test shape visible
without allowing CI to create kintone apps.

## Scope

The change adds `.github/workflows/ci.yml` and commits the provider documentation generated by the pinned
`make docs` target. Release automation and automatically running acceptance tests remain out of scope.

## Triggers and repository safety

The workflow runs for `pull_request` events and pushes to `main`. It has no scheduled or manual trigger.
Workflow permissions are limited to `contents: read`.

Concurrency is grouped by workflow and Git ref. A newer pull-request run cancels an older run for the same
ref, while push runs are not cancelled. Each ordinary job has a timeout so a stalled tool cannot consume a
runner indefinitely.

The workflow never reads kintone credentials. The disabled acceptance-test job does not map repository
secrets or set `KINTONE_DEV_ALLOW_ACCEPTANCE_TESTS`; removing only its disabling condition therefore fails
closed at the acceptance-test precondition rather than contacting kintone.

## Job architecture

Build, unit test, lint, and documentation verification are separate jobs. This makes failures visible as
distinct checks and lets GitHub Actions run the independent work in parallel. A shared composite action or
reusable workflow would add an unnecessary abstraction at the repository's current size.

All jobs use `ubuntu-latest` and `actions/checkout@v7`. Go jobs use `actions/setup-go@v7` with `go.mod` as
the Go version source and `go.sum` as the cache dependency path. The setup action caches downloaded modules
and Go build outputs.

### Build

The build job runs `make build`, preserving parity with local development.

### Unit tests

The test job runs `make test`, including its cache-bypassing `-count=1` behavior.

### Lint

The lint job runs the official `golangci/golangci-lint-action@v9` with an exact golangci-lint v2 release.
The action maintains its own lint cache while `actions/setup-go` maintains Go dependency and build caches.
The repository's `.golangci.yml` remains the single source of lint rules.

### Generated documentation

The documentation job runs `make docs`, whose `TFPLUGINDOCS_VERSION` pin makes generation reproducible. It
then fails if generated documentation differs from the checkout. The check covers both tracked changes and
new untracked files; `git diff --exit-code` alone would miss a newly generated resource or data-source page.

Generated `docs/index.md` is committed with the workflow. The existing `docs/design/` directory is outside
the paths managed by tfplugindocs v0.25.0 and must remain unchanged by generation.

### Disabled acceptance tests

The acceptance-test job is unconditionally skipped with `if: ${{ false }}`. Its job definition retains:

- a Terraform CLI matrix of `1.0.*` and `1.15.*`;
- `fail-fast: false` for eventual matrix execution;
- checkout, Go setup, Terraform CLI setup, and `make testacc` steps; and
- a job timeout longer than the Make target's 30-minute Go test timeout.

Terraform `1.0.*` is the minimum because protocol version 6 is supported by Terraform CLI 1.0 and later.
Terraform 1.1 introduced no provider-design incompatibility for this framework-only provider. The only
framework-related reason to require Terraform 1.1 would be combining framework and SDKv2 provider servers,
which this clean implementation does not do. Terraform `1.15.*` is the latest stable minor series at the
time of this design; Terraform 1.16 is prerelease software and is excluded.

Enabling this job later is a separate change. That change must establish an owner for failures, configure
the three documented development credential secrets, set the explicit acceptance-test guard, prevent
production targets, and account for apps that require manual cleanup.

## Validation

The workflow and generated output are configuration artifacts, so validation uses purpose-built checks
rather than a Go unit-test-first cycle:

1. Run actionlint against `.github/workflows/ci.yml` to validate workflow syntax and expressions.
2. Run `make build`, `make test`, and `make lint` locally.
3. Run `make docs`, then verify that the generated-documentation cleanliness check succeeds.
4. Introduce a temporary change under a generated documentation path, verify that the cleanliness check
   fails, and restore the temporary change.
5. Inspect the final diff and run the repository's whole-tree secret scan with redaction before any push.
6. After explicit push approval, verify that all CI jobs pass on a pull request against `main`.

Because the jobs invoke the same build and lint entry points used locally, a compilation error makes the
build job fail and a lint finding makes the lint job fail. No intentionally broken commit needs to be
published to demonstrate those failure paths.
